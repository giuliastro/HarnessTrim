# HarnessTrim 0.3.0 - Codex/Claude correctness and lower overhead

## Changes

- Claude Bash output is replaced with a shape-preserving object, not an invalid string.
- Codex preserves stderr, status and the complete result envelope in replacement feedback.
  Its optional Bash hook uses `continue: false` / `stopReason`, avoiding the code-mode
  promise rejection caused by `decision: block`.
- Both hooks ignore unsupported events/tools and image/rich shapes; receipt counts cover
  the full serialized response. They do not flatten errors or invent missing fields.
- Test-log reduction removes confirmed passes only. Unknown diagnostics and complete
  failure tails survive, including long assertion diffs and process exit status.
- New conservative Node TAP reduction handles flat passing subtests without hiding
  failures, suites, skip/todo, warnings, bailouts or unknown metadata.
- CLI startup loads neither MCP nor token vocabularies until needed. Only cl100k_base is
  bundled; the static startup graph is gated at 256 KiB. All chunks ship in the package,
  still with zero runtime dependencies.
- MCP skips disabled telemetry, counts pass-through tokens once, and isolates telemetry
  errors from successful tool results. Claude setup refuses to overwrite malformed settings.
- Documentation corrects the earlier unsupported claim that Claude universally ignores
  `updatedToolOutput`; the old adapter's structured-output contract was itself wrong.

## Validation and measurements

275 TypeScript tests and five Hermes Python tests pass locally. All ten workspace
TypeScript projects typecheck. The clean-package smoke test builds, npm-packs and installs
in an empty consumer; it checks every installer, executable/version, lazy MCP/tokenizer
paths, and the actual packaged Claude/Codex output contracts.

The ten Tier A fixtures measure **7747 -> 1876 cl100k tokens (75.8%)**, with **48/48 required
signals**, zero dropped audited signals, deterministic/idempotent output, and every fixture
inside the 25 ms p95 reducer budget. The new TAP fixture alone is **1666 -> 208 (87.5%)**.
See [raw Tier A report](0.3.0/tier-a.json). Adding TAP changes the blend; aggregate percentages
are not an apples-to-apples comparison to the previous nine-fixture suite.

Eight offline hook replays cover four fixtures in both adapters. The complete structured
TAP result is **1876 -> 259 tokens (86.2%)**; metadata, determinism and second-pass idempotence
are asserted. See [raw replay report](0.3.0/hook-replay.json).

Cold CLI hook startup, Linux and Node 24.20.0, 30 fresh processes per build, three warmups,
alternating order, telemetry disabled: median **71.648 -> 39.249 ms (45.2% lower)**;
p95 **124.858 -> 59.286 ms**. This is local startup, not LLM latency or total session cost.
The baseline is the starting `main` source at `06370ddeb805f41bbc286ed843300afd8d12722c`
(CLI source version 0.2.1), not an assertion about every historical npm tarball.
See [all raw timing samples](0.3.0/startup.json).

Reproduce from the repository:

npm tarball plus freshly generated Tier A and hook-replay reports to GitHub Releases.

## Upgrade

```sh
npm install -g harnesstrim@0.3.0
harnesstrim --version
harnesstrim install claude --apply
harnesstrim install codex --hook --apply
```

Run installation commands only for the harnesses/integration modes you use. Codex's
`--hook` remains optional; omit it to keep the instruction-based default. A global hook
can be installed with `--hook --global --apply` without editing project instructions.
Reload your harness and review/trust the hook. Existing PATH-based hooks use the upgraded
CLI; existing skill files and marker-guarded instruction blocks are not rewritten.

Older Bash pipe snippets may not preserve the original command's exit status. In Bash use:

```bash
( set -o pipefail; npm test 2>&1 | harnesstrim reduce )
```

See [detailed shell/adapter guidance](../codex-claude-optimization.md) for PowerShell,
structured-result contracts and compatibility boundaries. Setup never changes persistent
model choice or reasoning effort.

## Limits: what this release does not claim

No live Codex/Claude model session was run for this release. Protocol replay is not
end-to-end task-quality or billing evidence. Pin and validate installed harness versions;
older versions may ignore unsupported replacement fields, and native hook feedback can
be subject to size limits. Local receipts alone cannot prove model-visible acceptance.
Use the explicit pipe fallback where needed. `cl100k_base` is a cross-model proxy, not the
Claude billing tokenizer. MCP cannot erase tokens from text the model already supplied.
Live matched-task testing is the next roadmap gate; lower reasoning effort is not used
as a substitute for actual optimization.
