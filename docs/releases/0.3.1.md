# HarnessTrim 0.3.1 - reliable managed skill reinstallation

## Fix

Claude Code and Codex skill installers no longer treat an empty directory as an already-installed
skill. Transactional managers such as Token Harness intentionally remove owned files without
requiring directory deletion. HarnessTrim 0.3.0 saw the leftover directory name, skipped the copy,
and a subsequent verified setup failed because the advertised skill artifact was not recreated.

A skill is now considered present only when its `SKILL.md` entry file still exists. Existing
same-named user skills that contain `SKILL.md` retain the previous non-overwrite behavior.

## Regression coverage

- Unit coverage verifies empty nested skill directories are ignored and real skill entry files are
  still recognized.
- The clean npm-package smoke test now installs Claude and Codex, removes the owned files while
  leaving their directory shells in place, reinstalls both integrations, and SHA-256 verifies every
  restored skill file against the package's own `harnesstrim capabilities` digest contract.
- The normal typecheck, test, benchmark, package, installer, hook and cross-platform CI gates remain
  unchanged.

## Upgrade

```sh
npm install -g harnesstrim@0.3.1
harnesstrim --version
```

This patch does not change reducers, model choice, reasoning effort, telemetry semantics, or the
published skill contents.
